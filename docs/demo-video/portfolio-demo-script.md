# Tiny Stories Portfolio Demo Video Script

## Goal

Create a portfolio-ready demo video that proves Tiny Stories is a real playable system, not only a concept trailer.

The final video should mix three layers:

1. Cinematic AI-generated frames for atmosphere, emotional transitions, and chapter breaks.
2. Real product capture showing seed input, generation feedback, player choices, free-form action, advisor chat, state changes, and ending share.
3. Motion overlays that explain the system briefly without interrupting the gameplay.

Target length: 75-90 seconds.

Tone: story-first social drama, real product evidence, fast but readable.

## Core Narrative

The viewer should understand this in one pass:

> I type one dramatic seed. The system turns it into a playable drama with characters, hidden goals, live state, choices, free input, an advisor, and a shareable ending.

## Demo Story Seed And Reviewer Run Seed

The recorded trailer and the reviewer run serve different review jobs:
the trailer proves the product loop quickly, while `#/reviewer` gives a fresh
locked run that can be inspected in the app.

Use one polished English seed throughout the recorded video:

> At my wedding, the groom asks me to sign away my shares before the ceremony starts.

Use the current reviewer run seed for the Portfolio and Reviewer pages
captures and admissions screenshots:

> Minutes before the awards livestream, Mira the anxious publicist, Producer Han, Rina the backup dancer witness, Eun Sol the fan-channel reporter, and Choi the sponsor director gather in the control room after singer Seo Mina disappears. Mira must decide what to reveal before sponsors and fans panic, with no violence and no blackmail.

Keep those two evidence paths labeled separately. The wedding seed matches the
existing trailer keyframes; the Missing Singer Broadcast seed matches the
reviewer run and current portfolio page.

## Video Structure

### 0:00-0:05 - Cold Open

Visual:
AI-generated wedding keyframe. Slow push-in. Subtle rain/light movement added in Remotion.

On-screen text:
Stop writing stories. Survive one.

Voiceover:
What if a one-sentence drama prompt became a playable story?

Purpose:
Establish emotional hook before showing UI.

### 0:05-0:14 - Real Input

Visual:
Actual product capture. Open Tiny Stories create page. Cursor enters the seed:

`At my wedding, the groom asks me to sign away my shares before the ceremony starts.`

Click `Send opening`. If the visibility prompt appears, choose `Just me` for
the capture. When the Story Brief is ready, show the compact review summary and
click `Generate and enter story`.

Motion treatment:
Use a slight zoom crop on the textarea while typing. Add keystroke sound or small cursor pulse if audio is added later.

On-screen text:
One sentence in. A full run comes out.

Voiceover:
The demo starts from real user input, not a prewritten story.

Portfolio evidence:
This shot must be genuine browser capture.

- Cast

Voiceover:

### 0:32-0:44 - First Choice

Visual:
Actual play page. Show current narration and the option cards.

Player action:
Click an option with strategic posture, ideally something like:
- Ask to review the contract
- Force the witness to repeat the lie
- Signal the advisor before signing

If the generated live options differ, choose the option that best shows agency and consequence.

Motion treatment:
Pause on options for readability. After click, show the selected move and pending receipt:
`Move sent`, `Room reacting`, and `Next moves forming`.

Intercut:
AI-generated choice keyframe for a quick 0.8s flash.

On-screen text:
Choices are strategy, not page turns.

Voiceover:
Every turn gives a tactical choice. The system remembers what you picked and writes the next beat around it.

### 0:44-0:56 - Free-Form Action

Visual:
Actual play page. Open `Write your own move`.

Type:
`I smile, ask the lawyer to read the contract clause aloud, and secretly record his answer.`

Optional inner motive:
Open `Add inner motive` and type:
`If he hesitates, I know the witness was coached.`

Submit with `Submit with motive`.

Motion treatment:
Keep this section dynamic:
- Cursor typing in textarea
- Button press
- Loading shimmer
- New narration sliding in

On-screen text:
You can break out of fixed options.

Voiceover:
The player can also write a custom move. That is where it starts feeling like a game instead of a choose-your-own-adventure page.

### 0:56-1:07 - Advisor And State Feedback

Actual play page. Click floating advisor button.

Motion treatment:

Left: live play page.

Intercut:
AI-generated evidence/reveal keyframe as transition.

On-screen text:
Private advisor + live story state.

Voiceover:

## Editing Rules

Do:

- Let real UI prove the product.
- Use AI art as chapter punctuation and emotional glue.
- Keep every UI text crop readable for at least 1.2 seconds.
- Show at least one typed seed and one typed free-form action.
- Show at least one system feedback moment after the player acts.
- Preserve English UI throughout.

Do not:

- Make it only a cinematic mood trailer.
- Hide all product UI behind heavy blur or overlays.
- Over-explain with paragraphs of text.
- Show generated artwork pretending to be gameplay.
- Spend more than 5 seconds on any one static screen unless typing is happening.

## Capture Notes

Recommended capture size:
1920x1080 desktop browser.

Recommended product route:

1. Start at `#/create`.
2. Send the wedding seed with `Send opening`.
3. Choose visibility if prompted.
4. Review the Story Brief and click `Generate and enter story`.
5. Continue until at least one consequence is visible.
6. If the live ending takes too long, use an existing completed session for the ending evidence, but keep the seed/run visually consistent.

For a reviewer-run capture rather than a create-flow trailer, start at
`#/portfolio`, open the reviewer run, and keep the Missing Singer Broadcast title
and seed visible in the opening evidence.

Recommended motion in Remotion:

- Use real screen recordings as `<Video>` layers.
- Use generated keyframes as full-screen `<Img>` transition layers.
- Use masked crop windows to zoom into input, role, choices, advisor, and ending.
- Add a progress ribbon at the top of the video showing:
  `Seed -> Build -> Play -> Advise -> Consequence -> Ending`

## Version 2 Improvement Over Current Trailer

The current trailer mostly communicates the concept. This version should communicate:

1. I can type into the product.
2. The product responds with generated playable structure.
3. I can make fixed and free-form moves.
4. The UI updates with consequence and state.
5. The ending is a result of play, not a static mockup.

That makes the video stronger for a personal portfolio because it demonstrates both product thinking and engineering implementation.
